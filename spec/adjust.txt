## Problem

After registering a new user locally, the application redirects to `/app`, which produces a Next.js 404 because the repository does not have an `/app/page.tsx` route.

The existing authenticated application routes include:

* `/app/dashboard`
* `/app/students`
* `/app/curriculum`
* `/app/staff`
* `/app/academy`
* `/app/onboarding`

The correct default authenticated destination is `/app/dashboard`.

## Required fix

Inspect the current authentication and routing implementation first.

### 1. Registration redirect

Inspect:

`src/app/(auth)/register/page.tsx`

There is currently logic equivalent to:

```ts
if (user && !isLoading) {
  router.push('/app');
}
```

Change it to:

```ts
if (user && !isLoading) {
  router.push('/app/dashboard');
}
```

Do not change the registration API contract.

The successful registration flow should continue to:

```ts
router.push('/login?registered=true');
```

because the backend does not automatically authenticate the newly registered account.

### 2. Login redirect

`src/app/(auth)/login/page.tsx`

```ts

```

```ts

```

The intended logic is:

```ts
const returnUrl = searchParams.get('returnUrl');

if (returnUrl && returnUrl.startsWith('/')) {
  router.push(returnUrl);
} else {
  router.push('/app/dashboard');
}
```

Do not remove the open-redirect protection.
